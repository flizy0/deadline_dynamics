# Deadline Dynamics: защита

**Student Work Timing & Submission Study**

## Показ за 3–5 минут

**1. Overview: вопрос и вывод, 40–60 секунд.**

«Я исследую, связан ли момент начала индивидуального задания с его сдачей вовремя. Одно наблюдение — один студент и одно недавнее задание. Ответы собираю через Google Forms; цель — 120 подходящих наблюдений».

Покажите выбранный Real / Demo, число подходящих наблюдений и known. Прочитайте с экрана основной срок, размеры ранней и финальной групп, их доли и разницу в процентных пунктах. Группы относятся к одному выданному сроку, без разрешенного переноса.

«Это связь в нашей выборке, не доказательство причинности». При недостатке реальных ответов скажите, что сбор продолжается, и только затем явно переключитесь в Demo: его 144 наблюдения вымышлены.

**2. Data: исследование одной переменной, 40–60 секунд.**

Выберите планирование или время начала. Покажите распределение, рекомендуемый вид и альтернативу, затем таблицу точных чисел. Переключите анализ на связь с результатом.

«Распределение считает все подходящие ответы после фильтров. Доля вовремя внутри категории использует другой знаменатель: только ON_TIME + LATE. Пока не сданные и неизвестные исходы видны отдельно. Малые группы помечены, но это не проверка статистической значимости».

**3. Probability Lab: сначала случайность, 60–90 секунд.**

Покажите Overall sample и формулу из реальных чисел: onTime / known. Если known=0, выберите явно обозначенный Custom или Demo. Запустите одну группу и повторите ее: p не меняется, случайный результат может отличаться.

«Успех в модели — сдача вовремя. При n независимых испытаниях с одинаковым p число таких сдач X имеет биномиальное распределение. np — ожидаемое число, не обязательный результат каждой группы».

Запустите повторения, покажите simulation / theory и выберите порог рядом с распределением. Прочитайте «не меньше k из n», две вероятности и разницу. Откройте сходимость: оценка обычно стабилизируется с ростом повторов, но не монотонно.

Перейдите к Compare scenarios. Покажите две группы, затем распределения Started earlier / Final-day start при одинаковом n. «Центры могут отличаться, но распределения пересекаются. Не каждая ранняя группа лучше каждой финальной. Моделирование не доказывает причинную гипотезу».

**4. Method и Source: границы выводов, 30–40 секунд.**

Покажите Google Form, единицу наблюдения и путь от всех ответов к eligible и known. Назовите реальные даты и способ приглашения участников. Основные ограничения: добровольная неслучайная выборка, память, субъективность и неконтролируемые обстоятельства. Дополнительные симуляции не добавляют участников опроса.

## Ключевые места в коде

| Место | Объяснение |
|---|---|
| `StatisticsService.summarize` | Разделяет вовремя, позже, pending и unknown; known=ON_TIME+LATE |
| `StatisticsService.frequency` | Числа, проценты и все известные моды при равенстве частот |
| `StatisticsService.compare` | Две группы одного срока без продлений и разница их долей |
| `StatisticsService.simulate` / `simulateGroup` | Биномиальная теория, повторения, checkpoints и отдельная группа |
| `PageController` | Выбирает dataset / фильтры / режимы и передает Java-модели страницам |
| `LocaleConfig` / `SiteText` | RU/KK/EN, UTF-8 bundles, сохранение языка и query state |
| `explorer.js` / `lab.js` / local Chart.js | Представляют готовые серверные числа и управляют взаимодействиями |
| `SurveyService` / `GoogleCsvReader` | Проверяют ответы и CSV перед транзакционной записью |
| `SurveyEntity` / repositories | Соответствие Java PostgreSQL и сохранение данных |
| `SecurityConfig` | Защищает технический кабинет и POST через auth / CSRF |

`@Controller` принимает веб-запрос, `@Service` выделяет логику, `@Entity` описывает таблицу, `@Transactional` обеспечивает успешный пакет или откат. Java `record` хранит результат. Браузер не получает пароль PostgreSQL.

## Частые вопросы

**Почему не среднее время начала?** Диапазоны 3–4, 5–7 и 8+ не дают точного дня. Используются распределения и моды; неизвестные значения не заменяются нулем.

**Зачем разные диаграммы?** Используются виды из материала курса: простая столбчатая, линейная, круговая, процентная и групповая столбчатая диаграммы. Распределение сложности 1–5 начинается с линейного вида; номинальные исходы и перенос срока — с кругового. Связь категории с исходом показывается процентными полосами среди известных исходов или парными столбцами с точными количествами. Таблица всегда сохраняет точные числа. Категориальные диапазоны дней не выдаются за непрерывную гистограмму.

**Почему нет связи submissionStatus с outcome?** Это один и тот же результат: такой анализ был бы круговым и не объяснял бы дополнительный фактор.

**Почему pending исключены?** Протокол описывает известные завершенные сдачи. «Пока не сдал» остается видимым, но не приравнивается к завершенной поздней сдаче. Процент не относится ко всем заданиям; это ограничение отмечается.

**Что означает маленькая группа?** При known<20 доля может быть нестабильной. Предупреждение не означает статистическую значимость или ее отсутствие.

**Зачем Стерджесс и SD?** Это дополнительные показатели точных результатов симуляции X, не интервальных ответов опроса. Выборочное SD определяется при двух и более повторениях. Подробности свернуты.

**Все считает JavaScript?** Нет. Java рассчитывает counts, доли, модели и случайные результаты; Chart.js рисует их. Изменение порога пересчитывается сервером, а не отдельной браузерной статистической реализацией.

**Как данные появляются на сайте?** Google Forms → полная CSV-выгрузка → закрытый `/admin` → проверка → PostgreSQL → серверные агрегаты. Публичная навигация не показывает импорт. Автоматической синхронизации нет.

**Зачем сохранена `/survey`?** Для совместимости проверенного backend. Основной публичный инструмент сбора — Google Forms. Не собирайте одного человека через оба канала: анонимные повторные ответы разных каналов надежно не сопоставляются.

**Что будет при повторном CSV?** Неизмененная полная выгрузка не создает повторные записи. Измененные старые ответы без стабильных Google ID и частичные файлы требуют отдельной сверки. Ошибка в пакете отклоняет весь файл до записи.

## Перед показом

1. Укажите фактические даты и число ответов, не числа Demo. Не импортируйте учебные fixtures в реальную выборку.
2. Повторите маршрут Overview → Data → Lab → Method → Source. Проверьте язык, фильтры и мобильный экран.
3. Сверьте текущие результаты в `VERIFICATION.md`; исторические 58 тестов предыдущей версии не подтверждают новые изменения.
4. Не называйте выбранную добровольную выборку репрезентативной и не обещайте подтверждения гипотезы заранее.
5. Передавайте исходники и публичный адрес после развертывания, но не `local.env`, `.runtime`, пароли и необработанные ответы. Локальный `localhost` доступен только на вашем компьютере.
